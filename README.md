# Cisco Packet Tracer Network Project

## Project Overview

This project was completed as part of my cybersecurity and networking training. It demonstrates the design, configuration, and verification of a multi-network environment using Cisco Packet Tracer.

The lab connects HQ departments with a branch network and includes routing, IP addressing, network segmentation, traffic control, and redundancy.

## Objectives

- Segment departments using VLANs.
- Enable communication between permitted networks.
- Configure dynamic IP address allocation.
- Establish routing between HQ and Branch.
- Provide simulated Internet connectivity.
- Restrict Branch access to a protected HQ server.
- Configure and test Layer 2 redundancy.

## Technologies and Concepts

- **Cisco Packet Tracer** — network simulation
- **VLANs and inter-VLAN routing** — network segmentation and communication
- **DHCP** — automatic IP address allocation
- **OSPF** — dynamic routing
- **NAT/PAT** — translation of private addresses for simulated Internet access
- **Extended ACLs** — traffic filtering and server protection
- **PVST+ / Spanning Tree Protocol** — Layer 2 loop prevention and failover
- **LACP EtherChannel** — link aggregation and resilience

## Network Segmentation

| Network | Subnet | Default Gateway |
|---|---|---|
| HR | `192.168.10.0/24` | `192.168.10.1` |
| Finance | `192.168.20.0/24` | `192.168.20.1` |
| IT | `192.168.30.0/24` | `192.168.30.1` |
| HQ Server | `192.168.40.0/24` | `192.168.40.1` |
| Branch | `192.168.50.0/24` | `192.168.50.1` |

## Security Configuration

An extended ACL was configured to deny traffic from the Branch subnet (`192.168.50.0/24`) to the HQ Server subnet (`192.168.40.0/24`), while permitting other IP traffic according to the ACL rules.

The ACL was tested to confirm that Branch-to-server traffic was blocked while Branch-to-HR communication remained successful.

## Routing and Connectivity

OSPF was configured between the HQ multilayer switch, HQ router, and Branch router. A static default route on the HQ router points toward the simulated ISP.

NAT/PAT was configured on the HQ router and verified using NAT translation entries generated by Branch PC traffic to the simulated Internet destination `8.8.8.8`.

## Redundancy and Resilience Testing

- Configured PVST+ and selected the HQ multilayer switch as the root bridge for the relevant VLANs.
- Simulated a link failure and verified that STP converged to an alternate forwarding path.
- Configured LACP EtherChannel between HQ-CORE-SW and HR-SW.
- Shut down one EtherChannel member link temporarily and verified that the bundle remained operational.

## Verification Results

The following checks were performed in Packet Tracer:

- VLAN and trunk status
- EtherChannel status using `show etherchannel summary`
- OSPF adjacencies using `show ip ospf neighbor`
- Routing table using `show ip route`
- DHCP address bindings
- NAT translations using `show ip nat translations`
- ACL counters using `show access-lists`
- Successful connectivity between permitted networks
- Blocked connectivity from Branch to the protected HQ Server
